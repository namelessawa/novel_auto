## 本轮已经完成的改进

1. Narrator 输出持久化 `continuity_state`，下一 tick 注入不可重演事实与上一段尾部。
2. 高价值事件携带 `required_end_states`，正文与结束账本必须双重兑现。
3. `NarrativeStateGuard` 对正文、上一账本、声明账本、源事件做独立复验；失败最多两次
   外科修订，每次重新验收，最终失败则静默，不写入错误正文。
4. 证据协议要求逐字正文引文和真实账本路径；支持复合要求、列表路径和唯一物品别名。
5. 新增物品持有者、多人位置、到达/进入边界、雨水致损、独立新代价、无源专名等
   确定性护栏。
6. 修订器不得再对确定性冲突原样返回并声称“验证器误报”；补终态的长度上限由 45%
   调到 70%，仍受事实复验约束。
7. 新增跨段 `SectionEditor`：去重启、消重演、统一过渡，并以事实守恒验证器拒绝改写事实。
8. 新增读者知识、角色对白指纹、场景模式、视点轮换、伏笔兑现记录和章节封口契约。
9. 风格验收脚本支持 6-tick 压力序列、0/1/2 次定向修订、生产编辑链、逐 tick 状态/守卫
   trace，以及带明确 tick 边界的最终 judge。
10. 修复 reasoning/meta 前缀泄漏、过度省略、持续高潮、群像机械模板等问题。

## 后续优先级

1. **把事件终态改为结构化契约**：人物集合、目标位置、物品持有者、数量、损坏原因、
   新代价类型分别建字段，减少从自然语言推断“城墙外/城内/雨水/两人”的脆弱性。
2. **提高修订成功率**：下一轮真实 bench 应重点统计 `before → after → after_retry` 的救回率，
   而不是只看最终通过数；验证“禁止原样申诉”是否真正减少 no-op repair。
3. **增加正文完整性检查**：检测漏字、残词、异常短语和同音替换；当前 det 更擅长状态，
   对“浑浊发、折成小”这类流畅性损伤还不敏感。
4. **保留被拒候选的受控调试快照**：目前 trace 保存证据但不保存完整候选，人工复盘依赖
   引文；建议保存 hash + 首尾片段或仅 bench 环境保存全文。
5. **控制延迟与成本**：真实 3×4 tick 回归约 19 分钟；状态复验与修订应记录独立耗时，
   并考虑确定性预检先行、只对疑难项调用 LLM。
6. 在代表性 4-tick 达到稳定通过后，再跑全部 16 风格的 4-tick，以及 20/50 tick 长程漂移；
   当前不应直接把单 tick 32/32 外推为长篇质量。
